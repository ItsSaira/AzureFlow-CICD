00 / The Big Picture

What is CI/CD — and why use it?

CI/CD automates the path from a developer's code change to a tested, deployable release. The goal is repeatability, faster feedback and fewer manual deployment mistakes.

↻

Continuous Integration

Every change can trigger automated build and test checks. Problems are detected close to the commit that introduced them.

CODE → BUILD → TEST
→

Continuous Delivery

Once validated, the same artifact moves through controlled environments toward production instead of being rebuilt manually.

TESTED → RELEASED
◈

Why Azure?

Azure Pipelines orchestrates the workflow, ACR stores container artifacts, and App Service provides a managed web hosting target.

02 / Azure Services

The stack behind the delivery.

Each service solves one part of the delivery problem. Together they form a repeatable deployment system.

⚡

Azure Pipelines

Automates CI/CD with stages, jobs and tasks. A repository change can trigger the build and delivery workflow.

▣

Azure Container Registry

Stores the versioned Docker image produced by the pipeline so the deployment target can pull a known artifact.

☁

Azure App Service

Hosts the web application and can deploy a custom container image as part of the release stage.

◉

Monitoring

Track build history, deployment status, test results and environment health from a central dashboard.

⌁

Docker

Packages the application and its runtime dependencies into a portable container image.

⛨

Service Connections

Connect Azure DevOps pipelines with Azure resources using authenticated service connections.

05 / DevOps Concepts
Learn by following the flow.
Use the project as a visual study guide for the concepts behind modern CI/CD.



  
LESSON 01
Continuous Integration
Merge code frequently and let automated builds and tests detect integration problems early.
Build → Test → Feedback

  
LESSON 02
Continuous Delivery
Turn a validated build into a deployable artifact and automate release to the target environment.
Artifact → Release → Verify

  
LESSON 03
Containers
Package the application in a Docker image so the runtime environment is consistent across stages.
Code → Image → Registry

  
LESSON 04
Artifacts
Use a versioned container image as the hand-off between the build system and deployment target.
Immutable → Traceable → Repeatable

  
LESSON 05
Deployment Environments
Separate build, staging and production concerns so releases can be monitored and controlled.
Dev → Staging → Production

  
LESSON 06
Observability
Watch build history, deployment status and test trends to identify failures and regressions.
Measure → Detect → Improve
